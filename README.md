# CDK Starter

A starter project for AWS CDK with pnpm workspaces, Turborepo, and CDK Express Pipeline.

## Features

- **CDK Express Pipeline**: Wave/Stage/Stack deployment orchestration
- **Multi-Region**: us-east-1 (global) + eu-west-1 (primary)
- **pnpm Workspaces**: Native monorepo support with workspace dependencies
- **pnpm Catalog**: Centralized dependency versions with exact pinning
- **Turborepo**: Build orchestration with caching
- **tsx**: Fast TypeScript execution for CDK
- **esbuild**: Fast Lambda bundling
- **tsdown**: Shared package bundling
- **Vitest**: Fast unit testing
- **Generated CI/CD**: GitHub Actions workflows auto-generated

## Prerequisites

- Node.js 22+
- pnpm 10+ (`npm install -g pnpm`)
- AWS CLI configured with appropriate credentials
- AWS accounts bootstrapped in both `us-east-1` and `eu-west-1`

## Quick Start

### Bootstrap Prerequisites

Before deploying, bootstrap both regions if this is the first time deploying CDK apps in these accounts and regions:
```bash
# Bootstrap us-east-1 (global region)
cdk bootstrap aws://ACCOUNT_ID/us-east-1 --profile YOUR_PROFILE

# Bootstrap eu-west-1 (primary region)
cdk bootstrap aws://ACCOUNT_ID/eu-west-1 --profile YOUR_PROFILE
```

### Commands

```bash
# Install dependencies
pnpm install

# Build all workspaces
pnpm build

# Run tests
pnpm test

# Deploy to dev environment
pnpm cdk:deploy:dev
```

### Multi-Region Setup

| Region | Stacks        | Purpose                    |
|--------|---------------|----------------------------|
| `us-east-1` | global | Global resources like VPCs |
| `eu-west-1` | api, cron, website | Primary application region |

## Commands

### Build & Test

```bash
pnpm build          # Build all workspaces
pnpm test           # Run all tests
pnpm lint           # Lint all workspaces
```

### CDK Commands

```bash
# Diff against AWS (shows deployment order)
pnpm cdk:diff:dev
pnpm cdk:diff:stage
pnpm cdk:diff:prod

# Deploy to AWS (parallel within stages)
pnpm cdk:deploy:dev
pnpm cdk:deploy:stage
pnpm cdk:deploy:prod
```

The deployment uses `--concurrency 10` for parallel stack deployment within stages.

### Working with Workspaces

```bash
# Run command in specific workspace
pnpm --filter api build
pnpm --filter @app/utils test

# Add dependency to workspace
pnpm --filter api add lodash
```

## Environment Configuration

Environments are defined in `infra/config/index.ts`:

- **dev**: Development environment (branch: `develop`)
- **stage**: Staging environment (branch: `stage`)
- **prod**: Production environment (branch: `main`)

Each environment deploys to the same AWS account but uses:
- `eu-west-1` as the primary application region
- `us-east-1` for global resources like a VPC, IAM resources etc.

## Deployment Architecture

This project uses [CDK Express Pipeline](https://github.com/rehanvdm/cdk-express-pipeline) for deployment orchestration with a Wave → Stage → Stack hierarchy:

ORDER OF DEPLOYMENT
🌊 Waves  - Deployed sequentially.
🏗 Stages - Deployed in parallel by default.
📦 Stacks - Adheres to interstack dependencies, if none then all parallel by default.

```
🌊 shared (Wave 1)
  🏗 infra (Stage)
    📦 global (us-east-1) - IAM policies, shared resources

🌊 backend (Wave 2)
  🏗 app (Stage)
    📦 api (eu-west-1) - API Lambda with Function URL
    📦 cron (eu-west-1) - Daily scheduled Lambda

🌊 frontend (Wave 3)
  🏗 app (Stage)
    📦 website (eu-west-1) - CloudFront + S3 static hosting
```

## GitHub Actions (Generated)

GitHub workflows are automatically generated by CDK Express Pipeline:

### Diff Workflows (PR Comments)

| Workflow | Trigger | Environments Diffed |
|----------|---------|---------------------|
| `cdk-express-pipeline-diff-dev.yml` | PR to `develop` | dev, stage, prod |
| `cdk-express-pipeline-diff-stage.yml` | PR to `stage` | stage, prod |
| `cdk-express-pipeline-diff-prod.yml` | PR to `main` | prod |

Each diff workflow:
- Synthesizes CDK for the target environment(s)
- Runs `cdk diff` for each stage (shared, backend, frontend)
- Posts results as a comment on the PR

### Deploy Workflows

| Workflow | Trigger | Environment |
|----------|---------|-------------|
| `cdk-express-pipeline-deploy-dev.yml` | Push to `develop` | dev |
| `cdk-express-pipeline-deploy-stage.yml` | Push to `stage` | stage |
| `cdk-express-pipeline-deploy-prod.yml` | Push to `main` | prod |

Each deploy workflow:
- Builds all workspaces (via `.github/actions/build`)
- Synthesizes CDK for the environment
- Deploys stacks in wave order with `--concurrency 10`

### Regenerating Workflows

After modifying the pipeline configuration in `infra/index.ts`, regenerate workflows by running any CDK command:

```bash
pnpm --filter infra exec cdk synth '**' -c env=dev
```

## Dependency Safety

This project uses two layers of dependency safety:

1. **Exact versions**: No `^` or `~` - packages are pinned to specific versions
2. **Delayed installs**: pnpm requires packages to be at least 7 days old

To update dependencies, Renovate will create weekly PRs with updates.
